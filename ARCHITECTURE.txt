Chaos Pong - Architecture
=========================

Keep this file updated whenever the structure below changes (new entity,
new chaos effect, new top-level system). It should always reflect the
current code, not the original design intent.

Top-level layout
----------------
project.godot        Engine config: 2080x1200 viewport, GL Compatibility
                      renderer, autoloads, enabled plugins.
scenes/ + scripts/    One .gd per .tscn, paired by ext_resource. Scene
                      files hold layout/wiring; scripts hold behavior.
addons/               Third-party, not game code:
                        mcp_bridge - lets an AI agent run/inspect the
                          game from the terminal (editor + runtime TCP
                          bridges).
                        gut        - unit test framework.
test/unit/            GUT tests, one file per script under test.
.claude/settings.json Pre-commit hook: blocks `git commit` unless the
                      GUT suite passes.

Scene flow
----------
menu.tscn (main scene)
  -> Single Player / Two Player: sets GameState.two_player, loads game.tscn
  -> Options: builds one row per setting at runtime (options.gd), reading
     from and writing straight to GameState - a chaos-timer SpinBox and
     a CheckButton per chaos effect (on by default). See GameState below.

GameState (scripts/game_state.gd) - the only autoload holding settings
------------------------------------------------------------------------
Cross-scene state, read by Game at _ready() and written directly by
Options as the player changes each control (no separate "apply" step -
changes take effect next time a game.tscn is loaded).

  two_player               - set by Menu, read by Game
  chaos_interval            - default 30s, player-adjustable 10-60s via
                               the Options SpinBox; governs both the
                               first trigger delay and the repeat gap
  enabled_chaos_effects     - {effect_key: bool}, all true by default;
                               a CheckButton per key in Options
  CHAOS_EFFECT_KEYS          - the canonical ordered list of effect keys,
                               shared by Game (builds chaos_pool from it)
                               and Options (builds one row per key from it)

Core entities
-------------
Each is a self-contained Node2D with a class_name. None of them know
about each other - they only expose state and small helper methods
(get_rect(), bounce_off_*()). Game.gd is the only thing that connects
them.

  Paddle (scripts/paddle.gd)
    Vertical movement. Human input (W/S or Up/Down) or AI (reaction
    delay + aim error, tracks a Ball via ai_target). Draws an O or X
    marker keyed to `player`, not screen side. Can shoot a Projectile
    if `can_shoot` is set (see chaos effects below).

  Ball (scripts/ball.gd)
    Moves each frame, bounces off top/bottom walls itself, emits
    `scored(scorer)` when it exits past the left/right edge. Has a
    persistent `speed_scale` (for the permanent speed-doubling effect)
    and an `is_split_clone` flag (clones from the split effect vanish
    on scoring instead of resetting). `current_color()` picks the
    ball's color by priority: gold if `is_accent` (double points is
    active), else violet if `is_split_clone`, else the normal
    off-white - both flags inherited by clones spawned via split.
    `spin` (radians/sec) continuously rotates `velocity` each frame
    via Vector2.rotated() - speed-preserving curve, not a simulated
    force. `visual_spin_angle` accumulates at the same rate and drives
    a rotating indicator bar drawn across the ball whenever spin != 0
    (queue_redraw() called every frame while spinning, unlike the
    one-shot redraws the other flags use). Also inherited by clones.
    `decay_spin()` multiplies spin by SPIN_DECAY (0.7) and snaps it to
    exactly 0 below SPIN_STOP_THRESHOLD; called on every bounce off a
    paddle, wall, or Obstacle (not on a Projectile hit, which is an
    added force rather than a surface reflection) - spin winds down
    over a rally instead of curving at a constant rate until scored.

  HorizontalPaddle (scripts/horizontal_paddle.gd)
    The chaos-only top/bottom paddles. Same shape of AI logic as
    Paddle, but horizontal movement, always AI, no human input, no
    shooting, no marker. Both sit the same WALL_MARGIN off their
    wall, symmetric top/bottom - it's the score labels in game.tscn
    that were moved down (to y=110-190) to clear the top paddle's
    travel band, not the other way around.

  Projectile (scripts/projectile.gd)
    Straight-line movement, self-destructs off-screen. Only ever
    collides with a Ball (checked in Game, not here). `color` is set
    by Game per the firing Paddle's `player` (blue for player 1,
    coral for player 2, following identity through a swap like the
    O/X markers and scores do). On hit, Game calls
    `Ball.hit_by_projectile(projectile.velocity)`, which redirects the
    ball toward the projectile's travel direction and speeds it up by
    SPEED_INCREMENT - the same shape of change as a paddle bounce,
    including decaying spin, not just an added impulse.

  Obstacle (scripts/obstacle.gd)
    Falls straight down at a constant speed, self-destructs once past
    the bottom of the screen. Bounces a Ball off it via Vector2.bounce()
    (a real reflection off the obstacle-to-ball normal) but is NOT
    consumed on hit, unlike a Projectile - it keeps falling and can
    bounce multiple balls/times.

Game (scripts/game.gd) - the orchestrator
------------------------------------------
The only class with the full picture. Everything else is dumb by
design; rules connecting entities live here, not on the entities.

  State it owns:
    balls: Array[Ball]                  - starts at 1, grows via split
    horizontal_paddles: Array[HorizontalPaddle] - starts empty
    projectiles: Array[Projectile]      - starts empty
    obstacles: Array[Obstacle]          - starts empty, refilled on a
                                           timer once obstructions fires
    scores: {1: int, 2: int}            - keyed by PLAYER, not side,
                                           so a paddle swap doesn't
                                           transfer scoring credit
    chaos_pool: Array[String]           - remaining un-fired effects,
                                           built at _ready() from
                                           GameState.enabled_chaos_effects
                                           (disabled effects are simply
                                           never added to the pool)

  Collision handling (_process, every frame):
    All manual Rect2.intersects() checks - no Godot physics engine
    involved, this never needed real physics.
      paddle <-> ball
      horizontal_paddle <-> ball (only once third_fourth has fired)
      projectile <-> ball (projectiles never check paddles)
      obstacle <-> ball (only bounces if closing distance, to avoid
        re-triggering every frame while overlapping; not consumed)

  Chaos scheduler:
    First trigger at chaos_interval (from GameState, default 30s,
    player-adjustable 10-60s in Options), then every chaos_interval
    again. Each tick picks a random effect from chaos_pool and removes
    it - every effect fires exactly once, ever. Once applied, each
    effect stays permanent for the rest of the match, with two
    exceptions: double_points and spin (see below), both consumed by
    the next score instead. Once the pool is empty, nothing further
    happens for the rest of the match.

  Chaos effects (_apply_* methods), in the pool:
    double_speed   - multiplies every current/future ball's speed by
                     2x, permanently (via Ball.speed_scale)
    split          - each current ball becomes 4 (3 clones fanned out
                     at 90 degree angles); clones despawn for good when
                     they score, so ball count only trends back to 1
    swap           - swaps player/is_ai/ai_target between the two
                     Paddles; control assignment moves, screen position
                     does not
    third_fourth   - spawns two HorizontalPaddles (top/bottom), sets
                     third_fourth_active so their collisions start
                     being checked
    projectiles    - sets can_shoot on both Paddles; connects their
                     shoot_requested signal to Game, which spawns a
                     Projectile per shot (paddle-side cooldown caps
                     this at 1/sec), colored by the shooter's player
    double_points  - turns every current ball gold (Ball.is_accent,
                     inherited by split clones) and doubles the value
                     of the NEXT score only - that score consumes the
                     bonus: double_points_active goes back to false
                     and every ball in play reverts to normal color.
                     The only chaos effect that isn't permanent once
                     applied.
    shrink_paddles - halves both Paddles' height, permanently, via
                     Paddle.height_scale (a multiplier on the HEIGHT
                     const, not a change to the const itself)
    obstructions   - sets obstructions_active; Game then spawns an
                     Obstacle from a random x at the top every
                     OBSTACLE_SPAWN_INTERVAL (1.2s) for the rest of the
                     match - the only chaos effect that keeps doing
                     something after it fires, rather than being a
                     single permanent state change
    spin           - sets a random-signed SPIN_AMOUNT (Ball.spin) on
                     every current ball, inherited by split clones;
                     consumed by the next score (spin_active goes back
                     to false, every ball's spin reset to 0) - the
                     other non-permanent effect alongside double_points

  Debug-only UI:
    A countdown label ("Next chaos in: Xs") visible only when
    OS.is_debug_build() is true.

Known gaps (deliberate, not oversights - revisit if they start to bite)
-------------------------------------------------------------------
  - HorizontalPaddle duplicates Paddle's AI tracking logic (reaction
    delay + aim error) rather than sharing it, since the two also
    differ in movement axis, human-input support, and shooting.
  - HorizontalPaddle only tracks balls[0], not multi-ball-aware if
    split has already happened.
  - No on-screen announcement when a chaos effect fires (only the
    debug countdown shows anything).
  - Long games plateau: once every enabled effect has fired (by
    t = chaos_interval * count of enabled effects), nothing further
    escalates for the rest of the match - except obstructions, which
    keeps spawning obstacles indefinitely.
  - Options changes apply on next game.tscn load, not live mid-match -
    there's no "apply" confirmation step, GameState is just written
    to directly as each control changes.
